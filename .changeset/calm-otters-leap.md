**setup-callisto no longer verifies the release binary.** The `verification` input is gone, so the action installs the prebuilt binary, or falls back to crates.io when none exists for the platform.

- Why it matters: workflows generated by `callisto init` never set the input, so every run used the default `fallback`, which ran `gh attestation verify` and installed anyway when it failed.
- How to adopt: nothing to do for generated workflows. Release assets are still attested and `callisto release execute` still verifies attestations before uploading.

**Breaking:** `setup-callisto` no longer accepts `verification`. Workflows generated by `callisto init` never set it. If you added `verification: require`, `fallback` or `skip` by hand, remove the input; GitHub Actions warns about unexpected inputs.
