**1. `protection_rules` shape — confirmed via live `gh api` calls against real repos, not docs (GitHub's own reference page omits the object shape):**

- No protection at all → `protection_rules: []` (verified: `cli/cli`, `actions/checkout`, `npm/cli`, `denoland/deno`).
- **Critical finding: a non-empty array does NOT mean a human-review gate exists.** `rust-lang/rust`'s `bors` environment has `protection_rules: [{"type": "branch_policy"}]` — non-empty, zero human approval required. Environments can carry `branch_policy` and `wait_timer` rule types with no reviewers at all.
- Only `required_reviewers` entries gate on human approval, e.g. `pypa/pip`'s `PyPI` environment: `[{"type":"branch_policy"}, {"type":"required_reviewers","reviewers":[{"type":"Team","reviewer":{...}}]}]`.

**The spec's AC-004 as currently worded ("fails if `protection_rules` array is empty") is insufficiently strict** — it would pass an environment protected only by `branch_policy`, which restricts *which branch* can deploy but never requires anyone to click approve. AC-004 should instead assert the array contains at least one entry with `"type": "required_reviewers"` and a non-empty `reviewers` list, not merely "array non-empty." Recommend feeding this correction back into the spec.
