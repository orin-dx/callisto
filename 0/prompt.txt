## Summary

**Finding confirmed and fixed.** `derive_release_commit_decision` in `crates/callisto-graph/src/commands/release_decision.rs` looped over every canonical manifest, calling `manifest_version_at` against both `parent` and `release_commit` — each a separate `git show &lt;commit&gt;:&lt;path&gt;` subprocess spawn. For N manifests that was 2N spawns.

**Key discovery during investigation:** `callisto_model::CommandRunner` (`crates/callisto-model/src/exec.rs`) had no stdin-piping capability at all — every one of its ~30 implementors across the workspace called `.stdin(Stdio::null())`. `git cat-file --batch` requires piping a list of `commit:path` objects to stdin and parsing a byte-length-framed response stream. I verified the exact wire protocol empirically (`&lt;sha&gt; blob &lt;size&gt;\n&lt;content&gt;\n&lt;LF&gt;` or `&lt;object&gt; missing\n`) against real git before writing the parser.

**Fix implemented:**
1. `crates/callisto-model/src/exec.rs`: added `run_with_stdin` to `CommandRunner` with a default impl returning `CommandError::Unsupported` — backward-compatible, zero changes needed to any existing implementor.
2. `crates/callisto-cli/src/runner.rs`: implemented `run_with_stdin` for `CliCommandRunner` (the real production runner), writing stdin on a dedicated thread concurrently with `wait_with_output()` draining stdout/stderr, to avoid pipe-buffer deadlock on large payloads.
3. `crates/callisto-graph/src/commands/release_decision.rs`: replaced the 2N-call loop with `batch_manifest_blobs_at` (one `cat-file --batch` call per commit) + `resolve_batch_versions`. The batch parser is deliberately defensive: matches each response against its exact expected `commit:path` object string (not a generic suffix pattern), validates the `blob` type, checks the declared size fits and is followed by the protocol's separator byte, and fails the whole batch closed on any leftover/truncated output — any framing ambiguity fails closed rather than risking silent misattribution.
4. `manifest_version_at`'s parsing was extracted into `parse_manifest_version`, shared by the new batch path; the old per-object `manifest_version_at` wrapper was relocated into `#[cfg(test)]` since production no longer calls it (avoiding dead code), and its two existing tests are otherwise unchanged.

**Evidence of the before/after subprocess count:** added `derive_release_commit_decision_issues_exactly_two_batch_invocations_for_multiple_manifests`, a unit test with a recording `CommandRunner` double driving 3 canonical manifests through the real function — asserts exactly 2 `cat-file --batch` calls (would have been 6 `git show` calls pre-fix).
