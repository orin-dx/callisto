## Summary

**Bug fixed**: `ReleaseOperationId`'s hand-written `Ord` impl (in `crates/callisto-model/src/release.rs`) folded an `ArtifactUpload` role down to just `format!("{}|{}", slot.platform, slot.asset_name)`, dropping `ArtifactSlotId::attestation_policy` entirely from the comparison — even though the derived `Eq`/`Hash` includes it. Two artifact-upload operations with the same package/version/platform/asset_name but a distinct `attestation_policy` compared `Ord::Equal` while remaining `Eq`-distinct, breaking the `BTreeSet`/`BTreeMap` invariant. `validate_operations`'s `ids: BTreeSet&lt;ReleaseOperationId&gt;` and `stable_kahn_order`'s `edges: BTreeMap&lt;...&gt;` both key on this type, so the second such operation's insert silently returned `false`, and `ReleaseIntentV1::new` wrongly rejected the intent with `DuplicateOperation`.

**Investigation finding**: `Version` (used as a field of `ReleaseOperationId`) has no `Ord`/`PartialOrd` impl anywhere in the codebase (SemVer vs. PEP 440 aren't comparable via a single total order) — that's why both `ArtifactSlotId` and `ReleaseOperationId` already used `version.render()` in hand-written comparisons instead of comparing `Version` directly. This meant `ReleaseOperationId` itself cannot `#[derive(Ord)]` directly (it would fail to compile). I adjusted the fix accordingly: derived `PartialOrd`/`Ord` on `ReleaseOperationRole` (every variant's field type — `RegistryBindingId`, `ArtifactSlotId` — already implements `Ord`, confirmed by successful compilation), and kept a much-thinner hand-written `Ord` for `ReleaseOperationId` that delegates the role comparison wholesale to the now-correct derived `Ord` on `ReleaseOperationRole`, while still using `version.render()` for the `Version` field.

**Changes**:
- `crates/callisto-model/src/release.rs`: added `PartialOrd, Ord` to `ReleaseOperationRole`'s derive; deleted the now-dead `discriminator()` and `registry()` helper methods (used only by the old hand-rolled `Ord`); simplified `ReleaseOperationId`'s `Ord` to `(&amp;self.package, &amp;self.role, self.version.render()).cmp(...)`; kept `artifact_slot()` since it's used elsewhere (`validate_artifact_slot`, `validate_artifact_upload_roster`).
- Added a regression test `artifact_upload_ids_differing_only_by_attestation_policy_stay_distinct_under_ord` that constructs two `ArtifactSlotId`s differing only by `attestation_policy.workflow_commit`, and checks: (a) `Eq`-distinctness, (b) `Ord::cmp` is not `Equal`, (c) both survive a `BTreeSet&lt;ReleaseOperationId&gt;` insert, and (d) the full `ReleaseIntentV1::new`/`validate_operations` path accepts both operations instead of raising `DuplicateOperation`. Confirmed it fails on pre-fix code (`cmp` returned `Equal`) and passes post-fix.
- Added `.changeset/artifact-upload-ord-attestation-policy.md` (`callisto-model: patch`).
