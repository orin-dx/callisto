Based on the official Claude Code documentation, here's the precise answer:

## 1. **Interactive UI for Permission Rules**

Yes — use the `/permissions` command:
```bash
/permissions          # View current rules
/permissions edit     # Opens interactive rule editor
```

When auto mode is active, `/permissions edit` includes an **Auto mode** tab where you can add allow-rules without hand-editing JSON. You can also change the permission mode itself with **Shift+Tab** (in CLI/VS Code) or the mode selector (Desktop).

## 2. **Auto Mode vs. Allow-Rules**

**Critical distinction:** Auto mode's classifier and permission rules are *separate enforcement layers* that work **independently**. An allow-rule does *not* automatically bypass the auto-mode classifier. Instead:
- **Allow-rule** = permanent, persistent approval (saved to settings)
- **Classifier** = per-session decision by a second model evaluating "is this safe?"

The classifier will evaluate `gh pr merge` and `gh api` each time even if an allow-rule exists. To silence the auto-mode classifier on specific commands, you must also add them to the **auto mode classifier rules** (via the Auto mode tab in `/permissions edit`).

## 3. **Bash Rule Syntax**

The docs show Claude Code **strips shell wrappers and recognizes subcommands**, so:
- `Bash(gh pr merge *)` — matches `gh pr merge &lt;n&gt; --squash --admin` (with any flags)
- `Bash(gh api --method PUT *)` — matches `gh api --method PUT repos/.../rulesets/...` (with any trailing args)

However, **note the caveat:** rules match *each subcommand* in compound commands independently. For your two commands, you'd need:
```json
"permissions": {
  "allow": [
    "Bash(gh pr merge *)",
    "Bash(gh api --method PUT *)"
  ]
}
```

## 4. **Where the Rule Should Live**

For personal/machine-only rules that you don't want checked into the repo:
- **~/.claude/settings.json** (global, all projects)
- **.claude/settings.local.json** (project-local, git-ignored)

Do **not** put this in `.claude/settings.json` (the checked-in project file) unless the team wants it shared.

The docs explicitly state: "project's `.claude/settings.json` grant capability, so Claude Code applies them only after you accept the workspace trust dialog." Personal rules bypass that dialog.</result>
