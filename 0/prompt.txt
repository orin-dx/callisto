2. Key Technical Concepts

**Release pipeline**
- Rust workspace driven by just/moon/proto. The self-release workflow `.github/workflows/callisto-release.yml` runs: plan → build-artifact matrix → build → execute.
- GitHub Actions semantics:
  - A skipped ancestor skips any job without a status function.
  - `always()` runs a job even when the run is cancelled; `!cancelled()` does not.
  - Artifact-name uniqueness is scoped per run attempt.
- The GitHub App tag-push guard: `GITHUB_TOKEN` cannot push a tag, or create a ref via the API, whose `.github/workflows/` differs from every branch tip. No `workflows` permission scope exists for it. Normal-path releases tag the tip, so they work.
- Release model: `ReleaseIntentV1`, `ArtifactSlotId`, `validate_operation_roster`, `ArtifactSlotOutsideDecision`, `OperationState` (a payload-free enum; per-op evidence is not persisted), receipts, and recovery via `workflow_dispatch` with `release_source_sha`.

**npm platform packages ("Case E")**
- A package with `os`/`cpu` that is listed in an owner's `optionalDependencies` becomes a Platform manifest of that owner.
- New `PlatformPublish { registry, platform }` operation role; publishes run `npm publish <dir>` by directory.
- `ReleaseIntentV1` schema bumped 3 → 4.

**Registry observation**
- PyPI is observed through the PEP 691 JSON simple index via `curl -sS -i`. A yanked version counts as Absent.
- Tool-level retries are disabled so callisto owns retrying:
  - `cargo --config net.retry=0 info` (the flag must come before `info`).
  - `npm view --fetch-retries=0`.

**Tooling and environment**
- Worktree isolation for agents. `rtk` rewrites plain `git`, which the worktree guard refuses. An allow rule for `/opt/homebrew/bin/git` was added.
- `proto` was upgraded to 0.62.3 because moon 2.5.5 required a newer version.
- `strip = true` added to the release profile.
