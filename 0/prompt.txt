  ### 1. Design Decision: artifact_path Validation                                                                            
                                                                                                                              
  **Decision: Validate artifact_path via path.rs:25-70**.                                                                     
                                                                                                                              
  • Rationale:
      • Exfiltration Prevention: Leaving artifact_path unvalidated would allow path traversal or absolute paths
      (/etc/ssh/ssh_host_rsa_key, ../../secrets.pem) to be uploaded verbatim as public GitHub Release assets in CI.           
      • Codebase Invariant: Every user-authored path in callisto.toml ([changesets].dir, [[package]] changelog, [[package-    
      set]] changelog) is validated through callisto_model::workspace_relative.
      • Action Environment Alignment: Action runner scripts execute from the repository root; enforcing workspace-relative    
      paths guarantees reliable disk resolution across platforms.
  • Spec Changes:
      • Updated api_surface for SPEC-007-github-release-binary-assets.json:20-23 and
      SPEC-007-github-release-binary-assets.json:40-43 to specify validation via workspace_relative.
      • Updated SPEC-007-github-release-binary-assets.json:60 to reflect lexical path normalization without re-sorting.       
      • Added SPEC-007-github-release-binary-assets.json:73 (is_error_case: true) requiring absolute and root-escaping path-  
      traversal inputs to fail config resolution before any publish step executes.
