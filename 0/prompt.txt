Immediately before this summary, Gate A bugs were fixed and committed (`a255328`). The next bug to fix is **Gate B**: `commits_since_with_pathspec`'s broken since-bound in `crates/callisto-vcs/src/lib.rs`.

The broken code is at lines 317-320:
```rust
let stop_hex = since.map(|s| s.as_str().to_string());

let mut commits = Vec::new();
for info in revwalk {
    let info = info.map_err(|e| VcsError::Git(e.to_string()))?;
    let hex = info.id.to_hex().to_string();

    if let Some(ref target) = stop_hex {
        if &hex == target {
            break;  // BUG: silently drops commits on merged branches
        }
    }
    // ... rest of processing
```

The gate finding: "gix's rev_walk emits commits in traversal order, not ancestry order, so the break terminates the ENTIRE walk and silently drops commits that are reachable from HEAD but are NOT ancestors of since." Example: history `A-B-(S=tag v1)-C` on main, `B-D-E` on branch `feat`, merged as `M`. If the walk order is `M, C, S, E, D, B, A`, break at S means E and D are never seen — but they should be included (they're after the tag).

Fix strategy:
1. Build a `HashSet<String>` of all SHAs reachable from `since` using a separate `rev_walk`
2. In the main walk, use `continue` (not `break`) for commits in the excluded set
3. Add the `since` SHA itself to the excluded set

Then Track C: rewrite `MoonProjectGraph`, `MoonProject`, `MoonDependency` structs and update the `ProjectLocator` impl and all existing tests in `locator.rs`.

The test helpers `init_repo` and `run_git` already exist in `callisto-vcs/src/lib.rs` at approximately line 682, so the test fixture setup pattern is established.
