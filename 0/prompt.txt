  ## What changed structurally
  
  **1. Evidence-carrying observation.** `ProviderObservationV1` is now `Absent | Exact { evidence } | Conflict { reason } | Indeterminate { cause }`. `ProviderEvidenceV1` is closed and per-role (`RegistryVersion{version, checksum?, yanked?}`, `GitTag{peeled_commit}`, `ForgeRelease{tag_name, draft}`, `ArtifactUpload{byte_length, sha256}`); `ProviderConflictReason` and `ProviderIndeterminateCause` are closed enums derived from the cases the adapters already distinguish. `ReleaseOperationObservationV1::new` is the single constructor (deserialization routes through it) and rejects role-mismatched evidence (`E177`). `AbsentProof`/`ExactEvidence` are mintable only from an observation. Receipt `SCHEMA_VERSION` 1→2; `callisto schema --type release-receipt|release-state` added and guarded in `schema_guard_test.rs`.
  - Removed the duplicate `ForgeReleaseObservation` enum and its `unreachable!` bridge; `GitHubReleaseLookup::Indeterminate` now carries the HTTP status, which becomes `ProviderIndeterminateCause::ProviderStatus`.
  
  **2. Envelope first.** `ReleaseRunProvenanceV1` → `ReleaseRunEnvelopeV1` with one constructor `new(kind, orchestration_revision, intent, manifest_digest)`; profile, source revision and intent digest are *read out of the intent*, not asserted. Cross-field rules enforced at construction: source == intent source, manifest digest `Some` iff slots exist (both directions now), orchestration revision == every slot's attestation `workflow_commit`. It is persisted inside `ReleaseExecutionStateV1` (state `SCHEMA_VERSION` 1→2); `pending(intent)` is gone, replaced by `new(intent, envelope)`. `validate_for_run` gives `ReleaseStateError::MismatchedEnvelope`, message: *"release state at this path belongs to a different release run; pass a new --state path or remove the stale state file before retrying"*. The receipt takes its envelope from the state (`from_evidence` lost its provenance parameter); the CLI's after-the-fact assembly at `crates/callisto-cli/src/commands/release.rs` is gone — the envelope is built before `probe`/`execute`, and `--recovery` now only selects `ReleaseRunKindV1`, which the executor reads back off the envelope.
  
  **3. Transition table.** `release_transition::transition(current, event, run_kind)` is the only place a state is computed; `ReleaseExecutionStateV1::apply(id, event)` is the only mutator and takes the kind from its own envelope. `mark_attempting`/`mark_terminal` removed workspace-wide (grep for direct `OperationState` assignment returns only reads). Executor, reconstruction, recovery, store and all tests/fakes migrated.
  
  ## Deviations from the brief (and why)
  1. **Added an `AdoptedExact` event** (Pending→AlreadySatisfied, **Recovery only**) alongside `ObservedExactBeforeEffect` (Pending→AlreadySatisfied, any kind). Without it the `run kind` parameter would be vacuous, and the recovery-only privilege of adopting a pre-existing effect into a missing journal would be unenforced. Preflight uses the former, `reconstruct_missing_state` the latter.
  2. **`RecoveredExact` now yields `Published`, not `AlreadySatisfied`** (brief said Attempting→Published; this changes observable receipt outcomes for an interrupted-then-confirmed operation). This is the audit's #13 fix: "our attempt landed" is no longer conflated with "pre-existing".
  3. **`dispatch_registry` now always re-observes and requires `Exact` before success**, for every ecosystem, instead of trusting `PublishOutcome::Published`. Consequence: a **PyPI** publish now fails at dispatch (`RegistryPublishUnconfirmed`) rather than later at receipt construction — it already failed end-to-end (audit P1-4b), just later. Cost: one extra registry query after the confirmation poll for cargo/npm.
  4. **Collapsed sibling APIs** (audit #14): `execute_release{,_with_artifacts,_with_artifacts_in_recovery}` → one `execute_release(capability, store, permit, envelope, artifacts)`; `observe_release_operations{,_with_artifacts}` → one. `reconcile_release_execution` now takes `Option<&state>` so the read-only `release reconcile` path needs no envelope.
  5. **Fixed a pre-existing schemars defect in scope**: container-level `#[schemars(with = "…Wire")]` is ignored by the derive, so `ReleaseReceiptV1`/`ReleaseExecutionStateV1` were publishing their in-memory shape (snake_case, maps) instead of the wire shape. Replaced with hand-written `JsonSchema` impls delegating to the wire structs — otherwise the new schema guard would have pinned a wrong schema.
  6. **No `docs/` or `docs/specs/` updates.** `docs/07-self-release-lifecycle.md` and `SPEC-SELF-RELEASE-LIFECYCLE.json` now describe the old provenance-at-receipt-time model and the bare four-state observation. Out of scope for S1 per the brief, but they are stale and should be a follow-up.
  7. **New E-codes**: `E177` (observation unusable as evidence — role mismatch, internal defect), `E178` (run envelope invalid for this intent). `RemoteConflict::RegistryVersionDiffers` added.
