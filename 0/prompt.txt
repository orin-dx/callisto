  ### Recommended identity model (a design question for you)
  
  - A package is one directory; its internal key is the directory path. It has one or more names, each an `(eco, native name)` pair written `eco/name`.
  - Its display name is the primary manifest's name, shown bare when no other package uses that name in any ecosystem, otherwise as `eco/name`.
  - Promotion becomes display-only. Today, adding an npm `foo` changes the key and JSON output of an existing Cargo `foo` from `foo` to `cargo/foo`. That instability goes away if the key is not the display id.
  - Everything resolves by the rule in family A.
  - The spec changes this implies: WS-ID-02, 03, 04 and 07, WS-DISC-03, and both `api_surface` signatures in `docs/specs/workspace.json`.
