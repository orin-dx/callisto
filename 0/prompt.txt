### [Critical] `[[fixed-group]]` and `[[linked-group]]` config sections are parsed, validated, and then silently discarded — groups are always empty at runtime

- **Status**: CONFIRMED (fully traced)
- **Location**: `crates/callisto-graph/src/config/resolve.rs:265-269, 327`
- **Classification**: Policy Default That Ignores Config
- **Root Cause**: `config::load` builds `let raw_groups = RawGroupTable { fixed: ..., linked: ... }` (line 265-268), calls `GroupTable::validate_syntactic(&amp;raw_groups)?` to reject duplicate/empty groups (line 269), and then sets `groups: GroupTable::default()` (line 327) — an empty table — rather than calling `GroupTable::resolve(&amp;raw_groups, &amp;index)`. The function that would actually build the table from config is `GroupTable::resolve` in `groups.rs:136`, which is decorated `#[allow(dead_code)]` and is never called from any live code path. The consequence: `ws.config.groups` is always empty. `run_cascade` receives an empty `GroupTable`; `union_fixed`/`union_linked` in `aggregate.rs` always skip their loops; fixed-group and linked-group version coordination does nothing. A user who configures `[[fixed-group]] name = "core" members = ["crate-a","crate-b"]` in callisto.toml will get zero version synchronization and no error.
- **Failing Scenario**: Add `[[fixed-group]]\nname = "core"\nmembers = ["crate-a", "crate-b"]` to callisto.toml. Give only `crate-a` a changeset with `minor`. Run `callisto version`. `crate-b` is NOT bumped despite the fixed-group rule.
- **Severity**: Critical — silently breaks a major declared feature.
- **Verification Strategy**: Assert `ws.config.groups.fixed.len() &gt; 0` after loading a callisto.toml with a `[[fixed-group]]` block. Currently fails; would pass once `GroupTable::resolve` is called from `config::load`.

### [High] `SemVerVersioning` hardcoded in `bump_target` — crashes or silently misversions all PEP 440 packages during cascade

- **Status**: CONFIRMED (fully traced)
- **Location**: `crates/callisto-graph/src/cascade.rs:386`
- **Classification**: Strategy/Dispatch Hardcode
- **Root Cause**: `bump_target` unconditionally creates `let versioning = callisto_format::SemVerVersioning;` and calls `versioning.bump(&amp;base, sev)` regardless of the package's actual versioning grammar. When `base` is a PEP 440 version that is not simultaneously valid SemVer (e.g., `1.0a1`, `1.0.0.post1`, `2.0.0+local`), `SemVerVersioning::bump` returns `Err(BumpError::NotSemVer { .. })` which propagates as `GraphError::Bump`, aborting the entire cascade run for every changeset touching that package. Even for PEP 440 versions that happen to parse as SemVer (e.g., `1.2.3`), the bump output is a SemVer string, not a canonical PEP 440 string — potentially corrupting version fields.
- **Failing Scenario**: A Python package at `1.0a1` (pre-release) gets a changeset. `plan_version` → `run_cascade` → `bump_target` → `SemVerVersioning::bump("1.0a1", Patch)` → `Err(BumpError::NotSemVer)` → crash.
- **Severity**: High — crashes the primary version planning command for any workspace containing a Python package currently at a non-SemVer version string.
- **Verification Strategy**: Add a pypi package at version `1.0a1` to a test workspace, add a changeset for it, call `plan_version`. Currently returns `Err(GraphError::Bump)`. Should dispatch to `Pep440Versioning::bump` based on `base.grammar()`.

### [High] `[[package]] publish-to` config field is silently ignored — never read from resolved config

- **Status**: CONFIRMED (fully traced)
- **Location**: `crates/callisto-graph/src/config/resolve.rs:274-311`
- **Classification**: Policy Default That Ignores Config
- **Root Cause**: `RawPackageConfig` has `pub publish_to: Option&lt;Vec&lt;String&gt;&gt;` (raw.rs:68). The resolution loop in `resolve.rs` reads `raw_pkg.release_trigger`, `raw_pkg.tag_template`, `raw_pkg.changelog`, and `raw_pkg.pre_major_inference`, but never touches `raw_pkg.publish_to`. The resulting `PackageConfig` is always constructed with `publish_to: None` (line 304). The `publish_to` field on `PackageConfig` therefore carries `None` for every package. In `walk.rs`, `pkg_override.and_then(|o| o.publish_to.clone())` is never consulted — in fact the code doesn't even try to apply that field since the walk derives publish targets from manifests directly. A user who adds `publish-to = ["crates.io"]` to a `[[package]]` block expecting it to override the manifest-derived targets gets no effect and no error.
- **Failing Scenario**: `callisto.toml` has `[[package]]\nmatch = "my-internal-crate"\npublish-to = []` to mark a package as private. `plan_publish` still includes the crate in `rust_crates` because `publish_to: None` is never consulted.
- **Severity**: High — documented config key silently does nothing.
- **Verification Strategy**: Write a test that loads a callisto.toml with `[[package]] match = "x"\npublish-to = []` and asserts the resolved `PackageConfig.publish_to` is `Some(vec![])`. Currently resolves to `None`.

### [High] `pre-major-inference` config per-package setting always overridden with `OFF` in `aggregate`

- **Status**: CONFIRMED (fully traced)
- **Location**: `crates/callisto-graph/src/aggregate.rs:218`
- **Classification**: Policy Default That Ignores Config
- **Root Cause**: `aggregate()` builds an `InferenceWindowSpec` with `policy: PreMajorInferencePolicy::OFF` hardcoded. `PackageConfig` carries `pre_major_inference: Option&lt;PreMajorInferencePolicy&gt;` — populated correctly from `[[package]]` blocks — but `aggregate()` never looks up the package's configured policy. `apply_pre_major()` receives `OFF` and always returns the unremapped severity. A user who sets `pre-major-inference = "conservative"` to downgrade breaking-change commits from `major` to `minor` for a 0.x package gets no effect.
- **Failing Scenario**: `callisto.toml` has `[[package]]\nmatch = "my-lib"\npre-major-inference = "conservative"`. A conventional commit `feat!: breaking change` would normally produce `Major`. With the conservative policy it should be `Minor` for a 0.x package. Currently it stays `Major`.
- **Severity**: High — documented config key silently does nothing.
- **Verification Strategy**: Thread `pkg_override.and_then(|o| o.pre_major_inference).unwrap_or(PreMajorInferencePolicy::OFF)` into the `InferenceWindowSpec` construction instead of the hardcoded `OFF`.

Run `callisto version`. `plan_version` looks in `.changeset/pre.json` (wrong path), finds nothing, proceeds without pre-release state — potentially finalizing in wrong mode.
- **Severity**: Medium — silently breaks pre-release workflow when `changesets_dir` is non-default.
