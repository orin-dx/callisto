2. Key Technical Concepts:

- **Callisto**: Rust CLI + moon WASM extension for polyglot monorepo versioning (Cargo/npm/PyPI), byte-compatible with `@changesets/cli`
- **ApplyPermit**: Zero-sized compile-time dry-run enforcement token
- **Layer isolation**: Layer 1 (model, format) → Layer 1.5 (vcs) → Layer 2 (graph, manifests) → Layer 3 (cli, moon)
- **SemVerVersioning / Pep440Versioning / versioning_for()**: Dispatch function that selects versioning strategy by `VersionGrammar`; `versioning_for()` exists but was not called from `bump_target()` or `fixed_group_target()`
- **GroupTable::resolve()**: Function that builds fixed/linked group table from config — marked `#[allow(dead_code)]`, never called from production code
- **GroupTable::default()**: What is actually set in `config::load` — always empty, silently discarding all group config
- **PreMajorInferencePolicy::OFF**: Hardcoded in `aggregate()` — the per-package policy from config is never consulted
- **ReleaseTrigger**: `Changeset` vs `Auto` — the guard preventing inference for `Changeset`-trigger packages was never added
- **changesets_dir / ResolvedConfig**: Config field for the changeset directory, defaulting to `.changeset`; graph layer reads it but CLI commands (`add`, `pre enter`) hardcode `.changeset/`
- **parse_pre_json**: Deserializes `initialVersions` entries with hardcoded `VersionGrammar::SemVer` — breaks Python pre-release lifecycle
- **PublishPlan vs PublishReport**: Different JSON schemas; dry-run and real-run of `callisto publish` emit completely different structures with no `dryRun` discriminator
- **MoonProjectLocator**: Only checks `Cargo.toml` and `package.json` to infer ecosystem — silently drops Python packages
- **atomic_write**: All file writes gated by `ApplyPermit`; uses `NamedTempFile` + POSIX `rename(2)`; creates files with 0600 mode
- **PreMode serialization**: `PreMode` enum has `#[serde(rename_all = "lowercase")]`, but CLI JSON output hardcodes the strings `"pre"` and `"exit"` in 4 independent sites instead of using serde
- **`npm publish "$PKG"` vs `npm publish --workspace <name>`**: The action uses positional syntax (expects a directory path), while `callisto publish` uses the correct workspace flag
