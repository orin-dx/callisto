These patterns come from 71 findings in this repo, so they're hypotheses for other repos, not verified there. Roughly in order of how likely they are to bite elsewhere:

1. Hand-copied lists that drift.
   - What we saw: Option names written out in six places, a duplicated schema-version file, and a TypeScript union missing a variant Rust emits.
   - Check elsewhere: Wherever one concept (an option, an enum, a version) is spelled out in more than one file or language, add a single list plus a test or satisfies that fails when they differ.
2. String keys across a boundary.
   - What we saw: less precise read as less_precise, so a metric was always zero.
   - Check elsewhere: Look for stringly-typed keys passed between languages or processes. A missing key should fail loudly, not default to zero.
3. Graceful degradation applied to the wrong errors.
   - What we saw: Swallowed panics, an addon that logs provider errors at debug level and falls through to another engine, ignored exit codes, and dropped inputs with no count.
   - Check elsewhere: Soft failure suits user input. Misconfiguration, missing binaries and internal panics need a loud failure. Grep for catch {}, .ok(), unwrap_or_default(), || true and continue on unmatched entries.
4. Harnesses that don't match the real consumer.
   - What we saw: Benchmarks and measurements ran with the CLI's collapse default, but the Storybook addon uses a different one. Timings also mixed warm caches against cold, and fewer than N samples were reported as N.

5. Docs written from intent, not from code.
   - What we saw: "Glob patterns" that were substring matches, "five entry points" when there were 15, and numbers nobody could reproduce.
