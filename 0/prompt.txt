**1. Stop running `moon_wasm_sandbox` three times per `just ci`. [safe to just do, highest impact]**
Confirmed in `.config/nextest.toml` and `Justfile`: this is the single slowest test file (wasmtime sandbox spin-up, serialized to `max-threads=1`). It currently runs three times per `just ci`: once in `test`'s `cargo nextest run --workspace`, again explicitly in `wasm-check`'s `cargo test -p callisto-moon --test moon_wasm_sandbox`, and a third time inside `coverage`'s `cargo llvm-cov --all-features` (which re-runs the whole suite under instrumentation). Fix: have `wasm-check` skip re-running it (the build+check steps before it already prove the wasm artifact compiles; `test` already exercises it) — drop `wasm-check`'s trailing `cargo test -p callisto-moon --test moon_wasm_sandbox` line, or add an nextest exclude filter to `coverage`. Zero tooling change, pure Justfile edit.

**2. Don't run `coverage` on every local `just ci`. [worth discussing — changes what `just ci` means]**
Real CI (`callisto-ci.yml`) already runs coverage as its own parallel job on a separate runner — locally it's tacked onto the end of a serial pipeline, recompiling the entire workspace a third time under instrumentation. For local pre-PR checks, `just ci` minus `coverage` (i.e. `fmt-check lint test audit doc-check wasm-check`) covers correctness; coverage numbers are a reporting concern, not a merge gate a developer needs on every local run. Suggest a `just ci-fast` (no coverage) as the everyday default, keeping `just ci` as the full parity check.

**3. Upgrade `cargo-llvm-cov` 0.8.7 → 0.9.0+. [safe to just do, moderate impact]**
0.9.0 changed instrumentation to apply coverage flags only to crates that need them, instead of the whole dependency graph — meaningful here since `wasmtime` (a heavy transitive dev-dependency via `moon_pdk_test_utils`) currently gets instrumented too. One-line `cargo install cargo-llvm-cov --locked` bump, no config change.
