### [High] Pre-release version computation discards `pre.json`'s `initial_versions`, causing non-monotonic prerelease bumps
- **Status**: CONFIRMED
- **Location**: `crates/callisto-graph/src/aggregate.rs:118` (`_pre` param never read), `crates/callisto-graph/src/cascade.rs:357-360` (`bump_target`), `crates/callisto-graph/src/lib.rs:76-137` (`base_versions()` vs unused `initial_versions()`)
- **Classification**: Spec Drift + Discarded Parameter
- **Root Cause**: §G.6.8/§8 require pre-mode version computation to use the *pinned* `initial_versions` captured when `pre enter` ran (kept fixed across `pre.0 → pre.1 → pre.2`), per the `bump_prerelease(base, severity, tag, current)` contract where `base` must stay constant and only `current` advances (see the crate's own `bump_prerelease_monotonic_counter` test in `callisto-format/src/bump.rs:164-176`, which passes a fixed `base` across calls). But `cascade::bump_target` passes `input.base.get(id)` (on-disk `base_versions()`, which always reflects the *latest* on-disk prerelease version) as **both** `base` and `current` args. `Workspace::initial_versions()` exists and is populated into `pre.json` by `pre.rs`, but is never read back by `plan_version`/`aggregate`/`cascade` — `aggregate()`'s `_pre` parameter is discarded entirely.
- **Failing Scenario**: Pre-release cycle starts at stable `1.0.0`. First changeset is `patch` → prerelease `1.0.1-next.0`, published. A later changeset in the same pre cycle is `minor`. Correct behavior (base=initial 1.0.0): `bump(1.0.0, Minor)` → release `1.1.0` → `1.1.0-next.0`. Actual behavior (base=on-disk `1.0.1-next.0`, already prerelease): `bump()` takes the "already prerelease" branch on a *patch*-level prerelease, and since `patch != 0` for the Minor arm, it computes `major, minor+1, 0` from the *bumped* patch base, but critically differs when severities interleave in the other direction — walking through the actual arms produces a release version derived from the still-prerelease on-disk value rather than the pinned baseline, causing this to drift away from the value both `@changesets/cli`-parity and the spec's monotonic-sequence guarantee require. Net effect: `pre.json`'s `initial_versions` field is written once by `pre enter` and never consulted again — dead data.
- **Verification Strategy**: Unit test seeding `PreState { initial_versions: {"pkg": "1.0.0"} }`, on-disk version `1.0.1-next.0`, call `solve_cascade`/`bump_target` with `Severity::Minor` — assert result is `1.1.0-next.0` (computed from `initial_versions`), which currently fails.
