### 4. npm validate-before-mutate race window and coverage

**CONFIRMED CLEAN.**

`update_dependency_spec` in `/Users/gabe/Projects/callisto/crates/callisto-manifests/src/npm.rs:269-284` validates via an immutable `get` before any `get_mut` mutation. Since `PackageJson` is single-owner and Rust's borrow checker prevents concurrent access to `self.doc`, there is no race window.

The validation covers the primary section keyed on `kind` (e.g. `"dependencies"` for `DepKind::Runtime`). The `overrides`/`resolutions` tables are updated opportunistically after the primary section validates — these tables are secondary pinning entries, and updating them only if the name is already present there (lines 294-300) is semantically correct. The previous bug was that overrides/resolutions were mutated even when the primary section update failed; the fix correctly gates all mutations behind the primary section check.
