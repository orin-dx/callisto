## Bug confirmed and fixed

`crates/callisto-graph/src/tags.rs`'s `last_tag_for` ignored its `CommandRunner` parameter and called `callisto_vcs::GitRepository::discover(root)?` unconditionally. On `wasm32`, `discover` always returns `Err` (gix is native-only), so `TagIndex::build` — and therefore `Workspace::load` — hard-failed on the first package for every wasm/moon invocation (`status`, `plan-publish`, `validate`).

## Design

- **`fetch_all_tags(runner, root)`** (new, private): tries `GitRepository::discover` + `list_tags(None)` (full list, no glob) first; falls through (not `?`) to a single `runner.run("git", &amp;["tag", "--list"], root)` call when gix is unavailable — mirroring `changed.rs`'s established `if let Ok(repo) = ...` pattern.
- **`matching_tags(all_tags, template)`** (new, private): applies `globset::Glob` matching against the raw list in `callisto-graph` itself, reproducing `callisto_vcs::GitRepository::list_tags`'s exact matcher semantics (including its "uncompilable glob disables filtering" fallback) so selection is byte-identical regardless of which path sourced the list.
- **`select_from_tags`**: `matching_tags` + `select_last_tag` (pure).
- **`last_tag_for`**: kept, now implemented via `fetch_all_tags` + `select_from_tags` (fixes the standalone-call case too).
- **`TagIndex::build`**: now calls `fetch_all_tags` **once**, then loops packages calling `select_from_tags` on the shared list — eliminating N gix discoveries / N host round-trips.

No callers outside `tags.rs` needed changes (only caller was `TagIndex::build` itself; `lib.rs` just re-exports `last_tag_for`).
