## Findings, verified live in code as of 2026-08-23 (re-verify before trusting further — code may
have moved)

**1. Unbounded double revwalk — `crates/callisto-vcs/src/lib.rs:312`,
`commits_since_with_pathspec`.** Confirmed still doing two full, unbounded `rev_walk(...).all()`
calls: one from HEAD, one from `since`, then building a `HashSet` of the `since`-reachable side and
filtering by exclusion. This walks the *entire* repo history every time regardless of how close
`since` is to HEAD. Original audit measured ~2.05s vs ~13ms (100 packages/50k commits) — over 99%
wasted work. `gix` exposes a real bounded-walk API (stop the HEAD walk once every commit reachable
from `since` has been excluded, rather than walking to the repo's first commit) — use it instead of
the two-full-walks-then-exclude approach.

Important: a separate correctness bug in this exact function (a `break` vs `continue` bug losing
commits from branchy history — see the comment already in the function and commit `7e3391bc`) is
**already fixed**. Don't re-litigate it — but the bounded-walk rewrite must preserve that fix's
invariant (topological walk can visit `since` before emitting all in-queue commits on branches that
diverged before it), which is exactly why the original audit flagged this as needing an independent
review + before/after re-measurement pass rather than a naive bound. Get a second pair of eyes
(review agent) specifically on this invariant before merging.

**2. Per-package glob-matcher recompile — `crates/callisto-graph/src/tags.rs`, `matching_tags`
(called from `select_from_tags`, called once per package in `TagIndex::build`'s loop).** The tag
*list fetch* itself was already deduplicated in a prior session (`fetch_all_tags` is called once for
the whole build, not per package — see the comment at `tags.rs:111-118`). What's still live: every
call to `matching_tags` compiles a fresh `globset::Glob::new(...).compile_matcher()` and does a full
linear scan of the shared tag list, once per package. At 1000 packages / 41k tags the original audit
measured ~640ms wasted here. Fix: compile each package's glob matcher once (or cache by template
string, since multiple packages may share a template) rather than per package per build.

**3. Commit-inference pathspec bug — `crates/callisto-graph/src/aggregate.rs:177`.** Confirmed:
pathspecs passed to inference are built from `pkg.manifests.iter().map(|m| m.path.clone())` — the
manifest *file* path (e.g. `crates/foo/Cargo.toml`), not the package's source *directory*. This means
commit-based inference only ever matches commits that touch the manifest file itself, never real
source changes under the package directory — making the `inference` feature a near-total no-op for
its actual purpose. Fix the pathspec to cover the package's directory (mirroring how
`commits_since_with_pathspec`'s other callers scope pathspecs), regardless of whether `inference`
becomes default-on (that's a separate, deliberately-unresolved product decision — don't touch feature
defaults as part of this fix).
