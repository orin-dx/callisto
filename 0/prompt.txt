2. Key Technical Concepts:

- **Callisto Rust monorepo**: Multi-crate workspace with `callisto-graph`, `callisto-model`, `callisto-manifests`, etc.
- **PackageId variants**: `Bare(String)` and `Prefixed { ecosystem, name }`. ALL packages map keys in `ManifestWalkResolver::build` are ALWAYS `Bare` — `IgnoreWalkLocator` constructs IDs from raw manifest name strings via `PackageId::parse(name).unwrap_or_else(|_| PackageId::Bare(...))`. Calling `key.ecosystem()` always returns `None`.
- **Two-pass specificity**: Pass 1 finds first Prefixed match (`pattern.ecosystem().is_some()`); Pass 2 (fallback, `or_else`) finds first Bare match. Within each tier, first-match-wins (TOML declaration order).
- **Cross-ecosystem diagnostic**: After the packages loop in `ManifestWalkResolver::build`, iterate `cfg.packages`. For each bare rule, compute `BTreeSet<Ecosystem>` from `pkg.canonical_manifests().map(|d| d.ecosystem())`. If set has ≥2 elements, push one `Diagnostic { code: BareRuleMatchesMultipleEcosystems, severity: Warning, ... }`.
- **Napi fixture trigger**: A single directory containing BOTH `Cargo.toml` AND `package.json` with the same `name` creates ONE packages-map entry with TWO canonical `ManifestDecl`s (CargoToml + PackageJson). This is the only real AC-5 trigger. Two separate directories with same package name → `GraphError::DuplicatePackage`.
- **`ManifestDecl::ecosystem()`**: Returns `Ecosystem` directly (not `Option<Ecosystem>`), delegating to `ManifestFormat::ecosystem()`. No unwrap needed.
- **`Diagnostic` struct**: 7 fields (`code`, `severity`, `message`, `package`, `path`, `escalated_by`, `governed_by`), no `Default` derive. All fields must be written explicitly — no `..` shorthand.
- **`Package::canonical_manifests()`**: Existing helper at `crates/callisto-model/src/package.rs:24` that yields only `ManifestRole::Canonical` decls. Used in the diagnostic pass instead of inline filter.
- **`DiagnosticCode` serde**: `#[serde(rename_all = "kebab-case")]` on the enum. `BareRuleMatchesMultipleEcosystems` serializes to `"bare-rule-matches-multiple-ecosystems"` automatically.
- **canon → vector → lambda pipeline**: Formal dev protocol. Canon writes/audits spec; vector plans tasks with TDD; lambda implements TDD.
- **json.load/json.dump approach**: Used Python to patch the plan JSON file because manual string editing of JSON-with-embedded-code is error-prone (JSON escape sequences for `\n`, `\"` within string values are complex to handle manually in the Edit tool).
