  ## Design decisions
  
  1. **Cargo observation**: `cargo info NAME@VERSION --registry REGISTRY` via the existing bounded `CommandRunner` (`run_quiet`, `timeouts::REGISTRY_QUERY`), cwd = `context.root()` (the source workspace root, so its `.cargo/config.toml` registries + credentials apply). `cargo_registry_name()` maps the logical `cratesIo` key to cargo's built-in `crates-io`; any other key passes through. `--registry` is **never** omitted — that is the whole defence, so it is asserted directly (`the_observation_argv_always_names_a_registry`, `red_d01_every_cargo_info_observation_names_a_registry_explicitly`).
  2. **Classification** (`classify_cargo_info`): exit 0 + a `version: VERSION` line → `Exact { checksum: None, yanked: None }` (honest: `cargo info` reports neither); exit 101 + the exact phrase ``could not find `NAME@VERSION` `` → `Absent`; **everything else** (other exit, other message, exit 0 with no matching version line) → transient `Indeterminate` through the existing retry policy. The "could not find" match includes the spec, so an answer about a different crate can't be mistaken for this one. The yanked-fails-closed rationale is documented in one doc comment on `classify_cargo_info`.
  3. **PyPI refused at plan time**: `PypiRegistry::can_observe_versions() == false`, and a new `require_observable_registry(ecosystem)` is called from `derive.rs` where registry operations are built. New typed variant `ReleasePreconditionRequirement::ObservableRegistryClient` (E170) whose message names pip's ambiguity and both ways forward. I added a neighbour rather than reusing `ObservableProvider`, because that one is role-level (`checked_provider_for`) and its wording would have been wrong here.
  4. **Strict fake cargo models the defect rather than refusing it**: invoked without `--registry` the fake answers `version: X (from ./)` exit 0, exactly like real cargo. So if the production argv ever drops `--registry`, preflight sees `Exact` and the whole e2e suite fails with E174 — a lenient fake would have absorbed it.
  5. **Harness knobs moved to files** (the fakes are separate processes): `set_registry_flap` writes `<state>/flap` (`<honest> <absent>` counters, decremented by the fake); `set_registry_status(Some(401))` became `set_registry_unreachable(root, bool)` writing `<state>/unreachable`, which makes the fake emit the real transport-failure shape. Every existing e2e test's intent is preserved (lag→receipt, never-serves→no receipt, C5 already-uploaded→no success, C7 rerun not wedged).
  6. **Fixture envelope**: captured command runs are stored as `.cmd` files (`exit: N` / `--- stdout` / `--- stderr`). `just provider-contract` compares exit code + first line of each stream with digit runs masked.
