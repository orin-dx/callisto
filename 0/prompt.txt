3. Two git backends: gix plus a per-operation shell fallback
- Where: callisto-vcs lib.rs (GitRepository, ~700 prod lines), shell.rs (1094), access.rs (436); Cargo.lock has 69 gix* packages.
- Claimed benefit: "In-process git engine, no git subprocess spawns" (ARCHITECTURE.md §1).
- Why wrong: the CLI hard-requires a git binary before any workspace load (cli/src/workspace.rs:14-18,28). Release trust facts deliberately come from the shell backend (access.rs:115). Every read falls back to shell on any gix error (access.rs:16-25), so each read op has two implementations that must behave identically. A memory note records gix as a no-go under WASI, which is why ShellGit exists.
- Cost: ~2k LOC of duplicated semantics, a large compile-time dependency tree, and subtle fallback policy.
- Rec: after dropping moon (finding 2), keep ShellGit only and delete gix. GitDataSource can stay as a test seam.
- Effort/risk: M. Risk: slower commit walks on very large repos, but that path already runs whenever gix fails.

4. Conventional-commit inference is compiled out of the shipped binary but fully maintained
- Where: callisto-conventional (1205 LOC); the `inference` feature and CommitInference (graph/src/infer.rs:53-110); select_inference (cli/src/workspace.rs:34-47); config keys release-trigger and pre-major-inference; DiagnosticCode::PreMajorInferenceInert.
- Evidence: CLI default features are ["cargo","npm"] and the release build is `cargo build --release -p callisto-cli` (Justfile:11), so users get NoInference. Tests run --all-features (Justfile:21,47), so CI covers a binary nobody ships. The CLI depends on callisto-conventional unconditionally, but nothing in cli/src uses it.
- Latent defect: release_trigger is never read for behaviour, only shown in status.rs:97 and the transcript at release/derive.rs:547. aggregate() runs inference for every package regardless of trigger (aggregate.rs:173-222). With the feature on, packages set to trigger=changeset would get commit-inferred bumps.
- Rec: delete the crate, the feature, both config keys and the diagnostic. Or, if kept, make it default and gate it on ReleaseTrigger::Auto.
- Effort/risk: S-M, low.

6. Nine published crates and the MIT/FSL license boundary
- Where: workspace layout; callisto.toml fixed-group lists all 10 crates (fixtures is publish=false).
- Claimed benefit: third parties can consume "domain contracts" (ARCHITECTURE.md §1).
- Why little: no external consumers, pre-1.0. The "MIT foundation" callisto-model holds product internals: release.rs (3723 LOC), release_pr.rs (960), release_observation.rs, so it isn't a stable contract. Tiny crates (changelog 772 LOC, format 1578) each carry their own error enum and E-codes. manifests/src/atomic.rs is a "backward-compatible alias" for callers that don't exist. Every release publishes nine crates to crates.io and writes nine changelogs.
- Rec: collapse to a `callisto` lib plus `callisto-cli`, or keep internal crates for build parallelism but stop publishing them (cargo install needs published dependencies, so that means merging or vendoring). Drop the license split until a real consumer exists.

7. Error-code taxonomy bigger than users need
- Where: 143 code(E###) sites across 10 files (61 distinct E0xx, 78 E1xx); 32 callisto::* codes in cli/src/error.rs; moon's bare "E_LOCATE" string; the DiagnosticCode enum.
- Evidence: no user-facing reference anywhere (docs/, README and ARCHITECTURE have no E104 or E117). - Rec: one namespace; numbered codes only on the roughly 20 errors a user acts on; delete never-emitted variants.
- Effort/risk: S-M. Risk: JSON consumers that key on codes (only the action).

8. Dual package identity and dual package-config blocks
- Where: PackageId Bare/Prefixed (model/src/identity.rs, 347 prod lines). It accepts both ":" and "/" separators (identity.rs:38-55) and has wildcard matches() semantics. Related: promoted_siblings (graph/src/lib.rs:95-108), AmbiguousName E103, a second prefix parser in config/pattern.rs. [[package]] (exact) and [[package-set]] (glob) have near-identical fields (config/raw.rs:113-157) plus priority logic in walk.rs:316-372.
- Claimed benefit: napi packages that share a name across Cargo and npm.
- Cost: every lookup must handle ambiguity (the "Caller Contract" in core-identity.md), which has caused repeated bugs (Track E).
- Rec: internal ID is always (ecosystem, name); resolve bare names once at the input boundary; one separator. Merge [[package-set]] into [[package]] with a glob `match`, most specific wins.
- Effort/risk: M-L. Risk: the napi same-name case needs an explicit boundary resolver.
