### [Medium] `[project.optional-dependencies]` (PEP 621 extras) not visited by `iter_dependencies` or `update_dependency_spec`

- **Status**: CONFIRMED (`python.rs:213-282` traced — only `[project].dependencies` array and `[tool.poetry.dependencies]` table are visited)
- **Location**: `crates/callisto-manifests/src/python.rs:213-282` (`iter_dependencies`), `python.rs:300-370` (`update_dependency_spec`)
- **Classification**: Spec Drift
- **Root Cause**: PEP 621 defines `[project.optional-dependencies]` as a table mapping extra names to arrays of PEP 508 requirement strings (e.g., `[project.optional-dependencies] security = ["cryptography&gt;=41.0.0"]`). `iter_dependencies` checks `self.document.get("project").and_then(|p| p.get("dependencies"))` at line 215 — this gets only the top-level `[project].dependencies` array. The `[project.optional-dependencies]` sub-table is a sibling key, never accessed. `update_dependency_spec` has the same gap — it only modifies `[project].dependencies` entries and `[tool.poetry.dependencies]` table entries.
- **Failing Scenario**: Python app `app` declares an in-workspace sibling in its optional extras:
  ```toml
  [project.optional-dependencies]
  full = ["my-lib&gt;=1.0.0"]
  ```
  `my-lib` is bumped to `2.0.0`. Callisto considers `app` has no dependency on `my-lib` (since `iter_dependencies` never yields it), so `app`'s optional-extras pin is never rewritten. Users installing `app[full]` get `my-lib 1.x` while the workspace now requires `2.x`.
- **Verification Strategy**: Fixture `pyproject.toml` with a sibling under `[project.optional-dependencies]`. Assert `iter_dependencies` yields it. Assert `update_dependency_spec` rewrites it.

### [Low] `WorkspaceInheritance::inheritance()` silently swallows workspace version parse errors — produces a misleading downstream error

### [Low] `parse_changeset` gives a misleading `InvalidSeverity` error when a changeset entry name contains an embedded `"` character

- **Status**: CONFIRMED (`changeset/frontmatter.rs:49` traced; `write_changeset` at `changeset/mod.rs:228-232` correctly blocks the write path)
- **Location**: `crates/callisto-format/src/changeset/frontmatter.rs:49`
- **Classification**: Boundary Condition
- **Root Cause**: `split_name_and_rest` finds the closing quote of a quoted name using `after_quote.find('"')` at line 49, which returns the index of the **first** `"` after the opening quote. There is no backslash-escape convention (correctly documented in `WriteError::NameContainsQuote`), so a name like `"my "pkg"": patch` causes `find('"')` to terminate the name at `my `, leaving `pkg"": patch` as the "rest" field. This fails `Severity::from_str("pkg\"\"")`, producing `ParseError::InvalidSeverity { name: "my ", source: ... }` — a misleading error that blames the severity and truncates the name, rather than pointing to the embedded quote.
- **Failing Scenario**: A hand-edited changeset file with `"my \"pkg\"": patch` on an entry line (from a user who assumed backslash-escape would work). The error message says `invalid severity for package "my "` — the user gets confused because the severity `patch` is clearly correct and the package name is garbled.
- **Verification Strategy**: `parse_changeset("---\n\"foo \"bar\": patch\n---\n\nSummary.\n")` — assert the result is `Err(ParseError::UnclosedQuotedName)` or a new `ParseError::EmbeddedQuoteInName` variant, not `Err(ParseError::InvalidSeverity)`.
