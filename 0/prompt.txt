5. Problem Solving:

**Changeset deletion idempotency design question** (user asked): 
- Deleting before `callisto version` runs: works correctly (file gone = not aggregated)
- Deleting after release PR is already open: the PR has bumped manifests + deleted changeset files. Re-running `callisto version` reads already-bumped manifest versions with no changesets → empty plan → no-op. No "revert and regenerate" mechanism exists. This is the double-bump design flaw confirmed by the idempotency hunt.
- Current `apply_version_plan` has no transactional boundary: crash between manifest write and changeset deletion phases leaves workspace in double-bumpable state.

**Pre-release mode broken end-to-end**: The `test_pre_mode_blackbox_lifecycle` E2E test was confirmed as a false positive — it uses `contains("0.2.0")` which matches `"0.2.0-beta.0"`. The actual exit-mode finalization is never tested or implemented. `bump_target` in `cascade.rs` always calls `bump_prerelease` when `pre` is `Some`, regardless of `PreMode::Exit`.

**`[[package]]` config being entirely dead**: `ResolvedConfig.packages` is always `BTreeMap::new()`. All per-package overrides (release-trigger, tag-template, changelog, pre-major-inference) silently have no effect. Fix agent dispatched.
