  1. **justfile:125-134 and 137-142 (both new recipes): failures are silently swallowed.** Every other shebang recipe starts with `set -euo pipefail` (lines 76, 102, 118); these two do not, so only the last command's exit code counts.
     - `verify-real-tools` can exit 0 after a failed `npm install`, `pip install` or `pip download`, as long as the final `cargo install` succeeds.
     - Concrete case: wherever `uv` is on PATH, `uv venv` creates a venv without pip (that needs `--seed`). `python -m pip install` then fails with "No module named pip", and the recipe still exits 0.
     - Downstream effect: `just verify-real` then fails later with a confusing "gunicorn must be spawnable". The CI step in `.github/actions/install-registry-test-tools/action.yml` reports green and only the e2e tests fail later.
     - Fix: add `set -euo pipefail` and pass `--seed` to `uv venv`.
  2. **release_verify_real.rs:411 (missing-wheel test): flaky.** The mirror copies the wheel the moment it appears in pypiserver's store (`Duration::ZERO`), while pypiserver may still be writing it.
     - The index then serves a truncated copy. `copy_missing` never replaces an existing file, so the truncation is permanent.
     - Because the wheel is in this run's uploaded list, `pypi_files::compare` marks it as differing, and `confirm` returns a hard `PypiFileDiffers` error (pypi.rs:464).
     - Lines 285 and 359 have the same non-atomic `fs::copy` while the index is being polled.
     - Fix: wait a short settle time, and copy to a temp name then rename.
  3. **release_verify_real.rs:361-368 (delayed index): the timing assertion proves nothing.** `started` is taken before `execute`, which includes the Python build and upload, so `elapsed > 2500ms` holds whether or not callisto ever saw the index empty.
     - Completion only proves recovery if a confirm look happened inside the 2.5 s window. If callisto first looked after 2.5 s, the test still passes without exercising delayed visibility.
     - The index script's `log_message` is a no-op, so nothing records the miss.
     - Fix: log requests in the index script and assert at least one 404 after the upload.
  4. **release_verify_real.rs:198-218 (conflicting tag): does not check that nothing was published.** It asserts E167 and an unchanged tag only.
     - If callisto published both npm packages and only then hit the tag conflict, the test still passes.
     - Fix: add `assert!(npm.versions(DEPENDENCY).is_empty())` and the same for DEPENDENT, if stopping before any publish is the intended behavior.
  5. **release_verify_real.rs:234 plus local_registries.rs:29: port races.**
