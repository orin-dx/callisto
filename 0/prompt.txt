2. Key Technical Concepts:

- **Callisto**: Rust CLI + Moon WASM extension for polyglot monorepo versioning (10 crates at /Users/gabe/Projects/callisto)
- **napi-rs target triples**: 18-entry static lookup table mapping Rust target triples → Node.js `{platform, arch, abi}`. Rust uses `aarch64` but Node.js uses `arm64`; `x86_64` → `x64`; etc.
- **ManifestRole::Platform**: Variant for napi platform packages carrying `{platform, arch, abi}` fields
- **NapiTargetsIndex**: Reads `napi.targets` from package.json for each group's main package; previously a stub that always returned empty
- **napi_drift**: Set-difference between declared triples and group member triples; produces `NapiTargetAddedNotInMembers` and `NapiTargetRemovedStillOnDisk` diagnostics
- **PublishOutcome**: Enum with `Published` / `AlreadyPublished` variants (returned by `publish()`)
- **SubprocessRegistryClient**: Dispatches `RegistryClient` calls to cargo/npm/twine CLIs via `CommandRunner`; requires `load_plan()` call before `publish()` to thread per-package metadata
- **PEP 427 wheel normalization**: Requires collapsing RUNS of `-`, `.`, `_` into single `_` — char-by-char replace is wrong for names like `my--lib`
- **Injectable env closure pattern**: `fn check_credentials(plan, env: impl Fn(&str) -> Result<String, VarError>)` — avoids `std::env::remove_var` in tests (which is not thread-safe in parallel test runners)
- **Private Cargo registries**: Need `CARGO_REGISTRIES_<UPPERCASE_NAME>_TOKEN` (e.g., `CARGO_REGISTRIES_CLOUDSMITH_TOKEN`), NOT `CARGO_REGISTRY_TOKEN`
- **sequential constraint**: Per saved memory — parallel implementation agents fail on semantically coupled systems; parallel only safe for investigation
- **GroupMember variants**: `Package(PackageId)` and `PlatformManifest { owner, role, path, name }`
- **PUBLISH_TIMEOUT_SECS**: Named constant = 300 seconds for subprocess publish commands
- **CapturingRunner / ScriptedRunner**: Test helpers for verifying CLI arg construction vs. output classification
