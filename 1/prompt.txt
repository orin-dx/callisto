4. The failed release: two bugs

Bug 1: skipped ancestor (mine; fixed by #103, merged)

- Cause: release-candidate sits behind two exclusive gate jobs (verify on push, recovery-checks on dispatch), one always skipped. It uses always(), so it runs. GitHub skips any job with a skipped transitive ancestor unless its own if contains a status function. plan and build-artifact had none, so the chain to execute was skipped on both the push path and the dispatch path.
- Evidence: release-candidate had correctly set is_release_pr=true. PR #99 was merged from callisto/version-packages and the commit was verified. Earlier non-release runs (35551491179, 35537902908) looked healthy because version-pr has always(). Refs: actions/runner#2205, community discussion #45058.
- Why it wasn't caught: the policy checks were text-only, execute had never run in hosted CI, and the hosted preflight jobs don't touch this graph.
- Fix:
  - always() plus an explicit needs.X.result == 'success' on plan and build-artifact.
  - Policy rule: every job with needs must contain always().
  - New scheduler in the policy script. It evaluates each job's real if: under GitHub's implicit-success()-over-transitive-ancestors rule across 11 trigger and failure scenarios, and it rejects the c5578e6a workflow.
  - 4 mutants added.

Bug 2: cross-runner checksum (found by an independent bug-hunter review; fixed by #104, open)

- Cause: plan (Ubuntu) ran shasum -a 256 "$handoff_dir/release-intent.json" > ....sha256, which records the absolute path under its own RUNNER_TEMP. The macos-14 build-artifact leg verifies from a different RUNNER_TEMP, so "Verify handoff" fails with No such file or directory, and build and execute would be skipped. I reproduced it locally.
- Why it wasn't caught: Ubuntu legs and execute only pass because Ubuntu runners share a RUNNER_TEMP, and release-artifact-preflight skips that step.
- Fix:
  - (cd "$handoff_dir" && shasum -a 256 release-intent.json > release-intent.json.sha256).
  - The policy script now runs plan's checksum line, moves the files as another runner would, and runs the build job's verify line.
  - The execute receipt upload is now named release-receipt-attempt-${{ github.run_attempt }}. The old fixed name would collide on a re-run of a failed attempt (upload-artifact overwrite: false). That collision is inferred from the action's documented semantics, not observed.
  - 2 mutants added, 30 total, all rejected. just workflow-contracts, just zizmor and actionlint pass locally.
